# Modes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Modes (spec: `docs/superpowers/specs/2026-10-17-modes-design.md`) — temporary events (a trip) that focus the app while ON and collapse into one line outside it.

**Architecture:** A `Modes` table plus a nullable `modeId` on transactions, categories and tags; `Settings.activeModeId` marks the one ON. Joining is explicit at hand-entry call sites. Category aggregation leaves mode transactions out and a per-mode total adds them back as one slice. Mode CRUD lives in a focused DB extension; mode UI in `lib/features/modes/`.

**Tech Stack:** Flutter, Riverpod 2.6, drift (schema 85 → 86), go_router.

- [ ] `database.dart`: add the 4 tables to `@DriftDatabase`; `schemaVersion` 86; `if (from < 86)` creates the tables and `_addColumnIfMissing` for the 4 columns.
- [ ] Backup: export keys `modes`, `modeAccounts`, `modeCategories`, `modeTags`; import clears them first (before transactions/categories/tags/accounts) and loads `modes` after `groups`, the three link tables after accounts/categories/tags. `clearAllData` deletes links + modes and nulls `activeModeId`.
- [ ] `test/auto_backup_test.dart` SettingRow gains `activeModeId: null` (nullable → optional; only add if required).
- [ ] Tests (`modes_db_test.dart`): migration from v85 (drop the 4 tables + 4 columns, `user_version = 85`, reopen, tables exist); backup round trip keeps a mode, its links and a transaction's `modeId`.

### Task 2: Mode CRUD and lifecycle (`modes_db.dart`)

**Files:** create `lib/data/modes_db.dart`; Test `test/modes_db_test.dart`

- [ ] `addMode` validates name (1–40 trimmed), budget ≥ 0, end ≥ start, currency 3 letters known (`currencyForCode(c).code == c`), group exists; writes mode + link rows.
- [ ] `updateMode` same validation; rewrites link rows.
- [ ] `startMode(id)`: ends the currently active mode (if another), sets status active, `startedAt` (keeps first one), `Settings.activeModeId = id`.
- [ ] `endMode(id)`: status ended, `endedAt = now`, clears `activeModeId` if it was this one.
- [ ] `deleteMode(id)`: in one transaction — transactions' `modeId` → null; own categories/tags → `modeId` null + archived (categories `isArchived`; tags have no archive → keep, names stay unique); delete link rows; clear `activeModeId`; delete row.
- [ ] `setTransactionMode(txId, modeId)` (validates mode exists when non-null).
- [ ] Tests: add/validate; start ends the previous; end clears active; delete detaches transactions and archives own categories; setTransactionMode.
